Build a working **multi-user SaaS MVP in Replit** for Finnish construction project CO₂ calculation and reporting. Keep it simple, usable, and production-shaped, but do not overengineer. The app should have a clean, modern UI and a straightforward workflow that works end to end.

**Product purpose**
This is a SaaS tool for Finnish building projects. Users create projects, enter building and product data, attach emission factors, calculate lifecycle CO₂ by module, validate the data, lock a version, and export a report. The system must be deterministic, auditable, and version-based so results are verifiable for official use.

**Implementation goals**

* Multi-user SaaS aware
* Simple architecture
* Working login and tenant/workspace separation
* Good UI and table-based data entry
* Deterministic calculation logic
* Version locking and audit trail
* PDF and XLSX export
* No IFC/BIM import in MVP
* No API integrations in MVP
* No overengineering

**Recommended stack for Replit**
Use a stack that works fast in Replit:

* Frontend: React + Vite + TypeScript
* UI: Tailwind CSS + simple component library or custom clean components
* Backend: Node.js + Express + TypeScript
* Database: SQLite with Prisma ORM for simplicity
* Auth: simple email/password auth with session or JWT
* File export: server-side PDF and XLSX generation
* Seed data: include a hardcoded generic emission factor library

If needed for speed, a monorepo or single full-stack app is fine. Prefer simple structure over separation.

## Core SaaS model

### Tenant model

* `Tenant` = organization/company
* Each user belongs to exactly one tenant in the MVP
* All projects belong to one tenant
* Data must never leak across tenants
* Enforce tenant filtering in all backend queries

### Workspace model

* `Project` = building project/workspace
* Each project contains:

  * building data
  * versions
  * products
  * emission links
  * calculation results
  * reports

### Roles

Implement these roles:

* `admin`: manage users inside tenant, full access
* `editor`: create and edit projects, buildings, products, emission links
* `reviewer`: validate, approve, and lock versions
* `viewer`: read-only access

Hide or disable actions in UI based on role.

## Business rules

Implement these clearly:

1. Every query must be scoped by `tenantId`
2. A user only sees their own tenant’s data
3. Every project belongs to one tenant
4. Every version belongs to one project
5. Products belong to one version, not directly to project
6. Locked versions are fully read-only
7. New version is created by cloning a source version
8. Emission factor unit must match product unit
9. When emission factor is attached, store snapshot values on the product row:

   * emission source name
   * source type
   * unit snapshot
   * co2e per unit snapshot
10. Calculations must use the snapshot value, not live factor value
11. CO₂ formula:

* `product_total = quantityValue * co2ePerUnitSnapshot`
* `module_total = product_total * moduleShare`

12. Product module shares must sum to 1.0
13. Version can only be locked if validation passes
